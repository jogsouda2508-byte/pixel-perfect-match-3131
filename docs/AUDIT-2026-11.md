## Security findings

| # | Severity | Finding | Status |
| --- | --- | --- | --- |
| S1 | **Critical** | `get_login_email(username)`, `get_login_emails`, `get_reset_emails` are executable by **anon**. Anyone with the public anon key can turn a username into that account's real email address. **Verified.** (`20261102000000_multi_account_per_email.sql`) | Open: Phase 4 |
| S2 | **High** | `chat-media` bucket is `public = true` with an open `SELECT` policy: private DM photos/videos/files are readable by anyone who has the URL. (`20261030000000_chat_whatsapp.sql`) | **Patch ready** (`20261116000000_upload_security.sql`, not applied; see `docs/UPLOAD-SECURITY.md`) |
| S3 | High | `chat-media` has a size limit but **no `allowed_mime_types`**, so any file type (HTML, SVG, APK) can be hosted from your Supabase domain. Other buckets are restricted. | **Patch ready** (same migration, not applied) |
| S4 | Medium | The only rate limit found in the migrations is on `reports` (searched for `rate_limit`). Nothing found for signup, username/email lookups (S1), messages, follows or uploads. | Open: Phase 4 |
| S5 | Medium | Avatar upload validates type and size (good) but uploads the **original file as-is**: full resolution, and any EXIF metadata (incl. GPS location from phone photos) lands in a **public** bucket. | — | OK | All 50+ public tables have RLS; no wide-open write policies; no service-role keys or JWTs in the repo (**verified** by scan). | — |
